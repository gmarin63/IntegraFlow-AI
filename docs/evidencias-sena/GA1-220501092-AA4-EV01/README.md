# GA1-220501092-AA4-EV01 — Especificación de requerimientos funcionales y no funcionales

## Proyecto: IntegraFlow AI

### Introducción

Esta evidencia consolida los requerimientos funcionales y no funcionales iniciales de IntegraFlow AI a partir del levantamiento de información realizado y de las historias de usuario definidas para el proyecto.

### Objetivo

Especificar las funcionalidades y condiciones de calidad que deberá considerar el software para responder a las necesidades identificadas.

## Requisitos funcionales

| ID | Requisito | Prioridad | Relación |
|---|---|---|---|
| RF-01 | Permitir autenticación e inicio de sesión de usuarios. | Alta | HU-01 |
| RF-02 | Permitir administrar usuarios y sus roles. | Alta | HU-02 |
| RF-03 | Permitir registrar, consultar, actualizar y gestionar clientes. | Alta | HU-03 |
| RF-04 | Permitir cargar, organizar, consultar y gestionar documentos. | Alta | HU-04 |
| RF-05 | Permitir configurar y ejecutar automatizaciones sobre procesos definidos. | Alta | HU-05 |
| RF-06 | Presentar información consolidada mediante un dashboard. | Alta | HU-06 |
| RF-07 | Permitir generar reportes de la información registrada. | Media | HU-07 |
| RF-08 | Proporcionar asistencia mediante funciones de Inteligencia Artificial. | Alta | HU-08 |

## Requisitos no funcionales

| ID | Requisito |
|---|---|
| RNF-01 | Seguridad: la información y el acceso deberán protegerse mediante autenticación y control de permisos. |
| RNF-02 | Usabilidad: la interfaz deberá ser clara y facilitar el uso por parte de usuarios empresariales. |
| RNF-03 | Rendimiento: las operaciones habituales deberán responder en tiempos adecuados para el usuario. |
| RNF-04 | Disponibilidad: la plataforma deberá estar disponible de acuerdo con la infraestructura definida para el proyecto. |
| RNF-05 | Escalabilidad: la arquitectura deberá permitir incorporar nuevos módulos e integraciones. |
| RNF-06 | Mantenibilidad: el software deberá organizarse de manera modular para facilitar mantenimiento y evolución. |
| RNF-07 | Compatibilidad: la aplicación web deberá funcionar en navegadores modernos. |

## Priorización

Las funcionalidades relacionadas con autenticación, usuarios, CRM, documentos, automatización, dashboard e IA se consideran de alta prioridad. Los reportes se consideran inicialmente de prioridad media.

## Relación con la encuesta

La especificación se fundamenta en los resultados de la encuesta de 19 personas, especialmente en la identificación de errores manuales, duplicidad de información, falta de integración y alta aceptación de la automatización.

## Alcance

Estos requisitos corresponden a la especificación inicial y podrán refinarse durante el diseño, desarrollo, pruebas y validación del software.
