# Requisitos Iniciales — IntegraFlow AI

**Versión:** 1.0  
**Estado:** Borrador de especificación

## 1. Propósito

Establecer una primera consolidación de requisitos funcionales y no funcionales a partir de las historias de usuario y del levantamiento inicial de información.

## 2. Requisitos funcionales iniciales

| ID | Requisito | Prioridad | Relación |
|---|---|---|---|
| RF-01 | El sistema debe permitir autenticación de usuarios. | Alta | HU-01 |
| RF-02 | El sistema debe permitir gestionar usuarios según permisos. | Alta | HU-02 |
| RF-03 | El sistema debe permitir registrar, consultar y actualizar clientes. | Alta | HU-03 |
| RF-04 | El sistema debe permitir cargar, consultar, organizar y gestionar documentos. | Alta | HU-04 |
| RF-05 | El sistema debe permitir configurar y ejecutar automatizaciones. | Alta | HU-05 |
| RF-06 | El sistema debe presentar indicadores mediante un dashboard. | Alta | HU-06 |
| RF-07 | El sistema debe permitir generar reportes con filtros. | Media | HU-07 |
| RF-08 | El sistema debe proporcionar una interfaz de asistencia mediante IA. | Alta | HU-08 |

## 3. Requisitos no funcionales iniciales

| ID | Requisito | Categoría |
|---|---|---|
| RNF-01 | El sistema debe aplicar control de acceso según roles y permisos. | Seguridad |
| RNF-02 | La interfaz debe ser clara y usable para usuarios no técnicos. | Usabilidad |
| RNF-03 | La arquitectura debe permitir incorporar nuevos módulos e integraciones. | Escalabilidad |
| RNF-04 | Las operaciones relevantes deben contar con trazabilidad o registro cuando corresponda. | Auditoría |
| RNF-05 | La información debe protegerse mediante controles de seguridad adecuados. | Seguridad |
| RNF-06 | Los componentes deben diseñarse para facilitar mantenimiento y evolución. | Mantenibilidad |
| RNF-07 | Las integraciones externas deben manejar errores y fallos de comunicación de manera controlada. | Confiabilidad |

## 4. Fuente del levantamiento

El levantamiento inicial se apoyó en una encuesta aplicada a una muestra de 19 personas. Entre los resultados destacados, 16 de 19 participantes (84,2 %) consideran que los procesos actuales pueden optimizarse mediante automatización y 12 de 19 (63,2 %) seleccionan la automatización de tareas como la funcionalidad más importante de un nuevo sistema.

## 5. Estado

Estos requisitos son una **versión inicial** y deberán refinarse durante el análisis, diseño y validación del software. No deben interpretarse como una especificación técnica definitiva.
